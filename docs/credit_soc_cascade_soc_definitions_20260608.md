# 信贷网络级联失效与 SOC 判定口径说明

版本：2026-06-08 v1

本文用于统一项目中“级联失效”“大级联”“重尾”“幂律”和“严格自组织临界”的用法。主文档仍以 `project.md` 为准，本文给出更展开的解释。

## 1. 时间尺度

当前基线模拟有四层：

```text
scenario：一组固定参数和机制
  -> run：一个随机种子下的完整独立演化轨迹
     -> period：一批单位信贷尝试 + 一次期末流量结算和违约检查
        -> time_step：至多成功新增 1 单位信贷暴露的一次尝试
```

`time_step` 只是信贷增长步。每个 `time_step` 至多成功新增 1 单位信贷暴露；信贷建立本身同时增加贷款人的资产和借款人的现金/负债，因此不改变双方净资产。

`period` 是结算周期。一个 period 可以包含多个 `time_step`，数量记为 `K_t`。收入内生协议中：

```text
K_t = round(c * Y_(t-1))
```

其中 `c` 是上一期总收入到下一期计划信贷尝试批量的转换系数，不是单笔贷款规模，也不是实际投资支出比例。

当前基线只在 `period_end` 做违约检查。这意味着“级联发生在第 1 期”不是“第 1 个 time_step 发生违约”，而是第一期已经执行完 `K_1` 个计划信贷尝试，并完成第一次期末支出、收入分配和违约检查。

## 2. 级联失效的当前定义

个体 `i` 的净资产为：

```text
W_i = cash_i + loan_assets_i - debt_liabilities_i
```

违约条件为：

```text
W_i < default_threshold
```

当前基线 `default_threshold=0`，且严格小于零才违约。

一次记录的级联失效，也称一次 avalanche 或 collapse，是一次 `period_end` 内完整清算出的违约集合。流程是：

1. 期末流量结算后，找出所有已经净资产为负的节点，形成初始违约集合 `I_0`。
2. 把 `I_0` 放入清算队列。
3. 清算某个违约债务人 `j` 时，所有贷款给 `j` 的暴露 `E_ij` 被清零，债权人 `i` 的贷款资产下降，`j` 的债务负债解除。
4. 若 `wipe_defaulted_assets=True`，还清除违约节点 `j` 持有的贷款资产 `E_jk`，并解除对应借款人 `k` 的负债。
5. 每次清算后重新计算净资产；新变成负净资产的节点继续进入队列。
6. 队列为空时，本次级联结束。

现金在基线级联清算中不被额外扣除。级联传播来自资产负债表中的贷款资产减记和债务负债解除。

## 3. 事件规模和大级联标签

一次事件的规模定义为：

```text
collapse_size = 本次 period_end 中被清算的不同违约节点数
collapse_fraction = collapse_size / N
```

大级联标签定义为：

```text
critical_event = 1(collapse_fraction >= collapse_threshold_fraction)
```

常用阈值为 `collapse_threshold_fraction=0.10`。这个阈值只是人工分类口径，表示一次事件波及至少 10% 的节点。它不参与模型演化，不改变违约条件，也不能作为“临界”或 SOC 的证明。

“稳健的大级联”指的是大级联在多个独立 seed/run 以及相邻参数点中反复出现，并能报告重复率、置信区间或参数邻域稳定性。它说明系统存在稳健级联转变或过载区，但仍不等于 SOC。

## 4. 初始违约和传播新增的拆分

当前 `period_end` 是全系统统一流量结算。一次期末结算可以同时产生多个净资产为负的初始违约节点，因此一次记录事件不一定是经典 SOC 文献中的“单一微观触发”。

必须拆分：

```text
initial_default_count = |I_0|
propagated_default_count = collapse_size - initial_default_count
propagation_share = propagated_default_count / collapse_size
```

解释：

- `initial_default_count` 表示流量结算后、网络传播前已经违约的同步初始源数量。
- `propagated_default_count` 表示因其他节点清算和贷款资产减记而新增违约的节点数量。
- `collapse_size` 是二者之和。
- `single_trigger_event = initial_default_count == 1` 只说明传播开始时有一个初始违约节点；它仍是内生期末结算产生的，不是外部人为施加的单点冲击。

如果有限尺寸实验中总 `collapse_size` 随 `N` 增长，但增长主要来自 `initial_default_count`，就不能把它解释为传播过程接近临界。SOC 证据必须同时审计传播新增部分。

## 5. 本项目认为的 SOC 条件

本项目采用严格的操作性 SOC 判定。层级关系是：

```text
大级联出现 < 稳健级联转变 < 重尾 < 统计上可信的幂律 < 严格 SOC
```

严格 SOC 至少需要满足以下联合条件。

| 门槛 | 需要看到的证据 | 不足以证明 SOC 的现象 |
| --- | --- | --- |
| 无需精细调参 | 不依赖单一窄参数点；在相邻 `c`、固定 `K` 或相关机制邻域下仍有同类临界统计 | 只在一个参数点出现大事件 |
| 慢驱动、快清算 | 信贷增长与清算分离；avalanche 内部不继续加载信贷；长期状态不是每期持续失败 | 高 `c` 下几乎每期都有大事件 |
| 长期统计稳定 | 事件规模、活跃信贷、Gini、occupancy 等在 early/late 或滚动窗口中无系统漂移 | 非平稳 pooled events 的一张分布图 |
| 事件定义清楚 | 事件不主要由同步多源初始违约或跨期重复违约主导 | 只看总 `collapse_size` |
| 可信重尾/幂律 | 自动 `xmin` 的离散或有限支持幂律拟合可通过基本拟合优度；替代分布不能系统性更优；指数在 seed 和参数邻域中相对稳健 | log-log 近直线、固定 `xmin=2`、单个 `alpha`、KS 不拒绝 |
| 有限尺寸标度 | cutoff、矩或分布形状随 `N` 的变化与临界传播一致；传播新增部分也支持标度 | 绝对事件规模随 `N` 增长，但由初始违约广延增长主导 |
| 机制稳健性 | 对清算规则、检查频率、恢复/退出机制等合理消融不完全依赖某个实现细节 | 单一机制下的偶然重尾 |

因此，以下说法都需要避免：

- “出现了 `critical_event`，所以系统达到了 SOC。”
- “大级联在多次重复实验中稳定出现，所以就是 SOC。”
- “尾部分布画在 log-log 坐标下接近直线，所以是 SOC。”
- “KS bootstrap 不拒绝幂律，所以证明了幂律/SOC。”
- “`c=0.80` 下大事件很多，所以更接近 SOC。”

更准确的表述应当是：某个场景是否出现大级联、是否存在稳健级联转变、是否有重尾、幂律是否统计可信、这些证据是否共同满足严格 SOC 门槛。

## 6. 对当前实验结论的解释

当前已完成实验支持以下经验判断：

- 大级联和级联转变确实存在，尤其在高 `c` 或高固定 `K` 的过载区。
- 事件规模分布在部分场景中呈现重尾或局部幂律相似形态。
- 但严格 SOC 证据未满足：有限尺寸增长很大程度上来自同步初始违约；高 `c` 长期状态接近每期发生事件；重复违约占比高；部分尾部拟合被替代分布超越；长期平稳候选搜索没有找到通过门槛的场景。

所以当前结论应写为：在已实现 baseline、已扫描参数邻域和已测机制下，系统存在级联交叉、机制敏感重尾和过载吸引子，但不支持严格 SOC。
